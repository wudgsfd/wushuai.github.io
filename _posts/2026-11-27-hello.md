白天处理的是具体的事：一次实验、一份材料、一段要改的文字。晚上剩下的那些判断和犹豫，如果不写下来，第二天就散了。这个博客大概就是用来收这些东西的。

## 写什么

大体三类：

- **读过的东西**——论文、书、别人的观点，顺手写上自己的反驳；
- **做过的事**——推荐模型的一次实验、一版改了又改的稿子，成了或没成；
- **想不清楚的问题**——先把问题本身记清楚，答案以后补。

不追求完整。三百字也算一篇，写得糙也要写，因为不写就真的忘了。

## 为什么放在 GitHub 上

三个理由，都很实际：

1. **不要平台。** 写得再少，也不希望哪天搬不走。
2. **成本足够低。** Markdown 是纯文本，十年后还能打开；不需要数据库，也不需要备份策略。
3. **样式是自己的。** 这套页面的布局和配色是手写的，想改哪里改哪里，不用等主题作者更新。

## 怎么发一篇

在 `_posts/` 目录里新建一个 Markdown 文件，头部写几行信息：

```markdown
---
title: 标题
date: 2026-11-28 20:00:00 +0800
tags: [随笔]
description: 一句话摘要，会出现在列表和搜索结果里
---

正文从这里开始。
```

文件名用 `年-月-日-英文短名.md`，例如 `2026-11-28-reading-note.md`。**文件名必须是英文或拼音**，因为它会直接变成网址的一部分；标题照样可以写中文。

推送之后 GitHub 会自动构建，一两分钟内就能在「文章」页看到。

## 一条给自己的规矩

> 写具体的，不写正确的。空话谁都会说，具体的事只有做过的人才写得出来。

这句话先放在这里，以后每篇都拿它过一遍。
